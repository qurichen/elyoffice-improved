## 先试哪些内容

这轮主要验证 ElyDoc、ElyTable、ElyShow 的保存安全、恢复和进程生命周期。
它们分别处理文档、表格、演示；不是把原来的安装版自动升级，也没有替换
Windows 的文件关联。优化版编译成功不等于安装、升级、卸载都验证过。

建议从三份无隐私的副本开始：

1. 文档：中文、英文、表情、图片、页眉页脚、脚注和常用公式。
2. 表格：公式、日期、前导零、筛选、多个工作表和常用图表。
3. 演示：文字、图片、备注、动画以及你实际需要的字体。

每份都按“打开 → 编辑 → 另存副本 → 关闭 → 重开 → 与原软件比较”的顺序检查。
重点看内容、公式结果、分页、行列宽度、图片位置和图表，不只看能不能打开。
复杂文档仍可能出现脚注分隔线、段距、图表样式和字体量化差异。

## 保存时注意

- Doc 常用另存格式为 DOCX、ODT；Table 为 XLSX、ODS；Show 为 PPTX、ODP。
  导出与另存不是同一件事，不能靠随便改后缀完成格式转换。
- Windows 另存时省略后缀会采用应用的默认格式；手动写了受支持的其他格式
  则保留你的选择。覆盖已有文件仍应先出现确认。
- 取消另存不应清空草稿，也不应留下空文件。看见失败提示后先别关闭文档，
  换一个你有写入权限的普通文件夹再试。
- 不要把文档存入应用资料目录的 `work` 临时树。它会在下次启动时清理；
  本轮已加入拒绝直接打开、另存到该临时树的保护。
- 磁盘同步、共享文件夹和另一个编辑器可能同时修改文件。看到冲突提示时，
  先比较双方内容，不要直接选择覆盖。

## 崩溃恢复不是持续备份

应用定期保存恢复点，通常间隔十秒。最后一个恢复点之后的输入仍可能丢失；
正常保存、异地备份和版本历史不能由恢复点替代。

异常退出后，应用会把可恢复内容作为未保存副本打开。先检查内容，再另存到
自己的文档文件夹；不要把恢复副本当作已经写回原文件。首次启动的空白标签
与稍后出现的恢复标签也要区分。

加密文档的恢复还依赖凭据存储。若出现“恢复密钥仅本次运行有效”的警告，
重启后可能无法恢复该文档；应立即正常保存。不要把资料目录、恢复点或
凭据相关文件当作可以随便清理的缓存。

试用资料目录暂时使用较短路径。深层临时/资料目录仍有内核启动失败的已知
边界；缩短测试路径并不代表已经修好产品对任意长路径的支持。

## 本轮拼写功能的边界

随包保留的是英语词典，美式、英式、澳式和加拿大英语已做针对性检查。
这不等于支持中文语法检查，也不是云端智能校对。编辑本地文档不需要
把正文发送给 AI 服务；主动检查更新等其他功能可能另行联网。

## 怎样判断适合继续用

至少覆盖自己常用文件的一周试用：多次编辑保存后内容一致，取消、关闭和
冲突处理符合预期，程序退出后没有长期遗留的内核进程。重要文件继续保留
独立备份。一次自动化测试通过，不代表你的全部文件都兼容。

遇到问题时记录应用名、操作步骤、文件格式、是否必现和提示文字。优先用
删去隐私的最小样本复现；日志和截图也可能包含用户名、文件名或路径，
公开提交前先检查。暂时不要公开账号、密钥或原始敏感文档。

停止试用前，先另存所有草稿并备份试用目录中的个人文档。删除试用资料目录
会一起丢掉其中的设置和恢复点；不要顺手清理整个构建盘或其他应用资料。
