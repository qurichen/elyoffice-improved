# Ely Office：第18轮后的改进优化路线

规划日期：2026-10-25。目标：形成可长期试用的离线办公三件套，再发展扩展能力。
本文件是拟实施路线，不是已完成清单；进度继续以 `tasks/TASKS.md` 和实际验收为准。
研究覆盖七组主要办公套件及相关SDK，项目范围仍可补充，不代表穷尽所有开源仓库。
2026-10-26根据用户提供的建议补齐缺项，逐项判断见
[建议覆盖对照](optimization-path-advice-review-20261026.zh-CN.md)；原七阶段顺序保留。

产品主线是个人文档与数据由用户掌握：可靠保存、可恢复、变更可解释、兼容
别人发来的DOCX/XLSX/PPTX。离线、免费和无账号只是基础；差异化以可验证的
内容保护与个人工作流建立。实时协作、自研云同步、按Office功能数量对齐
不列入本路线目标，本地大模型仅为可选工具。

## 起点与技术方向

当前已验证的起点：

- Rust/GPUI界面、LibreOfficeKit独立工作进程；现有内核共72补丁。
- 第18轮最终230项不同测试通过：Doc64、Table68、Show92及共用控制6项。
  8项专测包含在Table68内；这不是全工作区或全部格式功能的覆盖率。
- 三应用优化构建通过，Table固定原生保存重开通过，独立最终R3 PASS。
  第18轮复用兼容worker和内核，不把它记成一次新的C++内核构建。
- 关闭窗口后仍有 `0x80070578` 诊断；复杂文档视觉、系统输入法、多DPI、
  加密原生恢复、多日使用及安装升级卸载仍有验收缺口。

依据：[第18轮记录](windows-validation-round18.md)、
[最终审查](reviews/round18-data-r3.md)、
[既有兼容性遗留项](ooxml-fidelity-round10.md#remaining-fidelity-work)。

主线继续使用现有Rust/GPUI、LibreOfficeKit和独立worker。在既有结构内吸收
可验证的修复、交互设计及模块边界；新引擎、WASM桌面重构和双引擎切换属于
另行评估的研发支线，需要先证明收益、迁移成本与往返兼容性。

## 实施顺序与依赖

```mermaid
flowchart LR
  A[基线与证据整理] --> B[保存与退出安全]
  B --> C[复杂文档兼容]
  B --> D[Windows交互与离线验收]
  C --> E[性能和长期运行]
  D --> E
  E --> F[独立安装试用版]
  F --> G[扩展和本地AI]
```

下列门槛是拟定的验收要求，不是已经取得的结果。每个阶段可以拆成多轮正常
工作量；轮数取决于复现和缺陷，不能用“再做几轮”替代验收。
P0/P1/P2表示实施优先级，不是对尚未调查问题的缺陷严重等级判定。

### 0：统一基线与证据（优先级P0）

交付：建立一份当前版本的能力与验收索引，把源码、补丁序列、worker、应用、
样本、测试方法和制品散列关联起来，区分内容、视觉、原生操作和安装验收。
更新兼容清单、试用指南和发布说明中的旧状态，历史失败和逐轮记录保持原样。

落点：`docs/compatibility.md`、`docs/windows-trial-guide.zh-CN.md`、
`docs/github-publishing.md`、`tasks/TASKS.md` 及现有制品清单。

门槛：每项“已支持”能找到当前适用的证据；例如特定深路径修复与任意UNC/
超长路径支持分开记录。旧版51补丁说明不能代表当前72补丁制品。
当前源码的 `updates.rs::LATEST` 已指向本fork的GitHub仓库；应核对整条
发布链，而不是照旧文档重新执行一次“从上游切换地址”。

### 1：保存、恢复、目标与退出安全（核心P0，其余按条目标级）

交付分为三个工作包，每轮只推进其中一类：

1. 先定位关闭后无效句柄：区分窗口生命周期、迟到后台回调和第三方平台层，
   建立同程序正常对照与稳定复现，再修根因。日志不能仅靠屏蔽变成“通过”。
2. 审计尚未覆盖的延迟对话框和菜单，继续保留读取时的Doc；普通即时输入仍
   按当前选区排队。复用已有严格入口，不把所有输入都改成快照操作。
3. 在当前内核上补原生恢复与失败矩阵：明文、加密、会话密钥警告、worker
   异常退出、只读/被占用目标、隔离存储中的空间不足及外部修改冲突。

落点：`crates/ely-office/src/{close,save,recover,autosave}.rs`、
`crates/ely-files/src/{save,recovery}.rs`、LOK的view/client命令与生命周期层，
以及现有Windows原生验收脚本。具体改动位置由复现决定。

门槛：取消不丢草稿、失败不破坏原件、不生成假成功或半成品、恢复内容经过
独立读取核对；跨文档/工作表的旧请求拒绝，正常慢/快点击仍通过。退出后
所属worker回收。句柄诊断须完成分类；未解决的非内容安全诊断须列明影响。
严格批次仍不承诺整批回滚；统一事务需要另行证明每类命令的撤销能力。

故障注入细化到生成快照、写临时文件、刷新、原子替换与更新恢复索引的
关键边界，只终止本轮所属测试进程。分别检查原件、最后完整恢复点及临时
文件；说明恢复间隔内可能丢失的输入，不承诺恢复点之后的每个按键都可找回。

P1补充：本地版本历史与用户指定位置的定期备份。现有恢复点和 `.bak` 接口
继续复用；新增正常退出后保留的历史、按版本查看差异、恢复为副本、容量/
保留期，以及备份目录、间隔、上次成功时间和失败提示。历史不随work/recovery
临时目录一起清理；未配置备份采用可关闭的提示，不把恢复快照称为独立备份。
文档加密和访问权限不能在历史、索引或备份中降级；保留来源文件与恢复副本，
保存与备份结果分别记录，不能把仅保存成功写成备份成功；完整版本浏览与
定期异地复制仍是待实现。

日志式保存按文档级编辑日志/增量恢复理解，列为P2研究项；现有原子替换和
完整恢复点不等于该能力。先量化缩短恢复窗口的收益，再验证操作序列、
重复回放防护、崩溃一致性与存储成本。若实施，持久层放在共用服务，含正文
的记录按受保护文档数据管理，与运行诊断日志分开且默认不导出到诊断包，
遵守原文档加密、访问权限及保留策略；未证明语义一致前不启用操作回放。

P1补充：不可信文档的操作系统级隔离。现有独立worker、默认禁宏及宏文件
风险模式保留；先验证文档授权、只读引擎/字体、受控临时目录和网络拒绝的
边界，独立进程或测试用Job不能作为已实现沙箱的证据。落点包括LOK客户端
启动、平台进程能力和相关原生测试，不改整机防火墙或全局权限。
验收含宏/外部链接负例、未授权读写和出站访问拒绝、正常保存与导出。
已有引擎停止提示和人工重启入口继续复用；自动恢复仅作为后续限次评估，
不盲目重放崩溃前操作或循环打开同一失败文件。

### 2：复杂文档兼容与字体诊断（优先级P1）

交付：复用现有合成回归与原生Office对照，先建立一组拟定30份的基础样本
（DOCX/XLSX/PPTX各10份），再按缺陷扩展；有许可的公开样本及脱敏副本
才进入语料库，不自动收集个人文件。样本数量不是覆盖率指标。

- Doc：中文/英文混排、样式、编号、交叉引用、分节、表格、脚注、页眉页脚、EQ/OMML、图片锚点。
- Table：现有默认列宽差异、字体度量、日期系统、公式结果、图表样式/标题。
- Show：文本框、母版、备注、图表、图片与实际需要的动画/媒体，分别验收。

落点：`patches/libreoffice`、LOK现有导入/导出及独立内容读取测试、三应用
相关界面。字体提示在ElyDoc已经存在，应完善诊断与覆盖，不重复新建。

内容安全P0补充：将未知部件、扩展属性、嵌入对象和关系纳入打开—保存—重开
对照；支持的保留路径须证明编辑后语义与引用完整。无法可靠保留时明确给出
风险、只读或另存副本路径，不静默丢弃，也不用回填旧XML掩盖编辑后语义丢失。
“通用无损往返”是逐特性目标，不能对任意文件承诺；禁宏等安全策略保持。
字体诊断补充实际替代字体与度量/分页差异，在许可允许时评估度量兼容字体，
不擅自捆绑或下载微软字体。

Table导入P0补充：现有预览、逐列类型和前导零/超15位整数按文本保护已有
实现；扩展显式严格模式，默认不推断类型，提供原始值、目标值及类型转换
差异预览。只有用户明确选择数值/日期转换时才执行，并提示精度或日期风险。
覆盖前导零、长整数、科学计数形式、日期样文本、空值与公式样文本，保存
重开后独立核对。严格模式是可选工作流，不把所有现有数值表无条件改为文本。

门槛：每个被修的问题先有修前失败与正常对照；依次比较打开、编辑、保存、
重开、PDF/打印输出。内容/公式/结构采用独立断言；视觉采用同字体、同DPI、
同软件版本的原生Office对照。逐样本约定容差与已知限制，不用固定常数
补列宽或段落位置，也不将截图相似等同于可编辑内容完整。

### 3：离线完整性与Windows交互（优先级P1）

交付：核心打开、编辑、保存、PDF输出及帮助在无账号、无网络条件下可用；
检查词典、必要字体与资源是否随包，不依赖CDN或在线转换。更新和AI作为
可选联网能力分别配置，网络失败不能阻塞核心编辑和保存。

同时验证中文系统输入法、组合输入与撤销、常用Office快捷键、键盘焦点出口、
拖放、多窗口和触屏/鼠标。拟测缩放100/125/150/175/200%，另测跨显示器
切换；当前175%具体修复不代替这些结果。

落点：三应用、`crates/ely-lok/src/view`、`crates/ely-ui`、已有GPUI组件与
平台适配层。通用交互优先回组件库，不按应用复制一套新控件。

门槛：隔离的新profile从启动即无网络，以及准备资源后离线两种场景均有
实际过程和保存内容证据；采用进程级受控测试，不改整机网卡或全局安全策略。
系统输入法和跨屏操作使用真实窗口验收，模拟按键不能冒充已测系统IME。
保存中/已保存/失败状态依据实际完成事件，取消和错误必须能区分。

补齐无障碍验收：在现有角色、段落文本桥接、键盘出口和减少动效基础上，
检查读屏可读的光标/选区、禁用状态、保存/错误反馈和焦点顺序；Windows真实
辅助技术验收与接口模拟分开，平台或GPUI缺口明确记为待补，不冒称已支持。

补充三件套专用的编译期无网络配置评估，覆盖更新、远端AI及引擎外部资源。
核对依赖与入口，再做实际出站拒绝测试；仅关更新开关或移除一个HTTP依赖
不能证明无网络能力。零遥测与零联网分别验收，不要求邮件/Git等模块失去
自身网络功能，也不把“未发现遥测”写成全套二进制已通过零联网认证。

### 4：性能、资源和长期运行（优先级P1）

交付：在同机固定样本上测冷/热启动、文档可编辑时间、输入到实际图块显示的
P50/P95、保存时间、内存/句柄/临时文件及worker峰值。借鉴模块化和按需加载
思路，只优化实际剖析出的瓶颈；不直接套用其他项目的性能数字。

落点：既有 `tests/perf/{bench,soak}.py`、Windows资源运行器、LOK图块及
输入队列。既有基准工具有历史审查缺口，先复核当前平台的计时与判定可靠性。

门槛：先记录并冻结本机基线和回归预算，再做优化；同时通过内容与交互检查。
在已保存、关闭的固定大小文档循环中检查资源是否回落，和持续增长的撤销历史
分开统计。安排拟定8小时受控长跑及至少一周副本试用，保留异常与中止记录。
长跑单独安排，不占用每一轮正常修复的全部工作量。

### 5：独立安装与可回退的试用发布（优先级P1）

交付：形成明确标为实验/试用版的独立安装包，应用、worker、内核、补丁与
来源清单配套；验证fork身份、资料目录、更新清单、资源下载地址和现有散列
校验行为。当前已有安装/更新代码，重点是当前fork实际包的完整验收。

落点：`packaging/windows`、`crates/ely-platform/src/{install,update,release}.rs`、
`crates/ely-ui/src/updates.rs`、现有安装测试与发布文档。

门槛：在隔离位置验证新装、升级、失败恢复、卸载及并行保留旧版；不删除用户
文档或另一个安装的资料。实际包的应用/worker协议和内核来源匹配，下载地址
来自预期发布渠道。签名状态、校验和、许可证、对应源码及已知限制如实随包。
干净环境构建与实际安装验收单列，不能由本机增量编译成功替代。

补齐fork的Windows/macOS持续集成，Linux按现有交付范围保留；原Gitea发布
流程先核对归属和上传行为，不直接当GitHub工作流执行。缓存键关联平台、
工具链、引擎提交、补丁序列和构建选项，缓存命中不代替干净环境重建。
复用现有许可证收集，增加与实际包对应的机器可读SBOM，覆盖Rust依赖、
引擎外部库、字体及捆绑工具，记录来源、版本、许可证与制品关联。
可重建的过程与逐字节可复现的结果分开记录，未测一致性时不宣称后者。

达到此门槛后再决定是否替换日常安装版；执行发布或安装依照当时的用户指令。

### 6：脚本、扩展和可选本地AI（优先级P2）

交付：先选两个真实使用场景，如区域批量格式与文档检查，复用已有命令契约
形成小范围类型化入口，再考虑公开SDK。参照Univer的命令/Facade边界及
ONLYOFFICE的插件设计，明确目标、可读写范围、撤销能力与错误结果。

库与CLI补充：已有 `ely-files`、`ely-lok` 继续复用；逐步分离共用服务与
GUI上下文，使转换、检查、批处理由命令行和界面调用同一份逻辑。现有
`ely-office` 仍依赖GPUI，不能将“已有crate”当成完整无界面接口已完成。

个人工作流P2候选分别立项，排在安全与兼容基础之后：

- 本地全文检索与标签：只索引用户选择的目录，处理撤销授权、删除、索引
  更新和加密文档边界；索引可能含正文，不能当成可随意公开或清理的普通缓存。
- 超大CSV与本地查询：评估流式读取、分页及本地查询，先定容量/内存预算；
  不能把当前全文件读取预览或Calc工作表上限当成超大文件处理能力。
- 外发前检查并生成清理副本：复用已有PDF清理能力，另验DOCX/XLSX/PPTX
  的作者、批注、修订、隐藏对象/工作表等。先预览具体改动，修订由用户选择
  接受/拒绝/保留；不自动改原件，不把删除作者字段称为完整匿名化或脱敏。

脚本或本地AI先在副本上生成可审查的修改，执行仍走原Doc与严格命令入口；
持久区域标识、完整事务回滚和第三方扩展隔离按需要独立实现、独立验收。
模型可选、显式配置，不成为离线打开编辑保存的前置依赖。

2026-10-28用户同意增加ElyDoc轻量选区翻译：默认关闭，用户配置模型端点，先预览
选区再主动发送，首版仅中英结果预览和复制；与独立ElyAgent分开，不做工具执行。
密钥存系统凭据库，连接按profile和地址隔离，正文不落盘、不进日志；本地服务是否
转发由用户配置决定，不因回环地址就承诺离线。后续插入/替换须逐次确认并可撤销，
整篇保排版翻译、摘要与润色另行验收。此功能包不替代安全、兼容与长期试用主线。

门槛：旧目标拒绝、越界访问拒绝、取消保留原件，内容与输出可独立核对；
不声称兼容VBA、COM、XLL或ONLYOFFICE插件。无第二个使用者前不建设通用
扩展平台；邮件和完整八应用扩展排在主力三件套的长期试用之后，云协作不在本路线范围。

## 每轮落地方式

按用户当前正常工作量偏好，每轮选择一个可独立验收的问题包，流程保持：

1. 固定样本、来源与断言，真实复现；正常对照也要通过。
2. 根因修复，保留早期失败和测试读法修正历史，不为通过而放宽检查。
3. 只跑与改动匹配的检查；共用层改动覆盖三个应用，C++改变才重建相关内核。
   不因编译成功就跳过运行，也不在没有新疑点时反复跑同一整套测试。
4. 受影响的原生保存/重开与独立内容断言，随后按仓库规则独立审查。
5. 报告完成内容、未完成项和制品范围，然后停下等待下一轮指令。

当前230项是第18轮基线，后续测试可能增加；各轮重叠项不相加成总覆盖数。
上游候选更新先三方比较，复用原有72补丁，避免覆盖已完成的本地保护。
内核与vendor修复保持小而独立，每个补丁关联来源、复现和回归，记录与上游
是否重复及可回迁状态；适合的准备为上游补丁，不重写历史以压低补丁数量。
保存编排、版本历史、备份和索引优先放在已有共用层，格式/排版根因确在引擎
时仍允许最小内核修复；“完全不改LibreOffice”不作为本项目的约束。
