# 第25轮：CSV按文本保留导入

2026-10-28。正常规模，沿数据保护路线实现严格导入的第一步：用户显式开启
“全部按文本保留”，避免数字、科学计数和日期样文本自动转换。普通数值导入
仍为默认。运行验证已完成，并经独立R1审查通过；未安装或上传。

## 实现

每份待导入文件有独立的text_only选择，初始为false。开启时，预览列类型
显示为文本、逐列转换控件禁用，并有中英文说明；过期的列回调也拒绝在此
模式或扫描期间更改类型，列宽变化后不再直接越界索引。

有效Import选项由原选择克隆而来，文本模式覆盖全部已扫描列为Text。保存
在对话框中的普通列选择不变，因此关闭开关可恢复之前的跳过/日期等选择。
开关本身不触发扫描；编码、分隔符和引号仍按原流程扫描，模式保留，最终
采用完整文件扫描得到的最大列宽，覆盖预览范围外后来出现的列。

沿用不可读编码/扫描未完成的导入门禁及旧扫描asked/Arc身份检查。原文件
字节不改；数字/日期转换限制位于应用的已有列类型选项，不增加worker协议、
过滤器格式或C++补丁。诊断只新增模式布尔值，不记录文档正文。

## 实际回归与数据

在Table87内，不另外叠加；各进程退出0、无忽略、SKIP、资源守卫或强制清理，
worker峰值不超过1。Table耗时170.81秒，目录检查0.02秒，测试编译53.28秒。

新用例覆盖UTF-8、UTF-16LE的开启开关→实际导入→XLSX保存→关闭→重新打开；
关掉开关恢复手动Skip/DateYmd选择；分隔符重扫后保留模式，并保护只在第11行
出现的新列（超出8行预览）；普通模式继续把7/1.50读成数值。

测试中的单元格读法会trim两端，不能用它证明空白保留；另用Python标准库
CSV和ZIP/XML逐格独立读取真实文件，结果见`text-content.json`：

- 两份文本模式输出精确A1:I1九格，全部为shared-string，无公式或额外格。
  内容包括00123、20位整数、`1.234567890123456789E+19`、`2026-10-28`、
  `0.12345678901234567890`、字面`=1+2`、`-0`、中文/emoji，以及精确的
  `  padded  `，两端各两个空格保留。
- 修前/后的普通模式输出均为A1数值7、B1数值1.5、C1文本`=1+2`，无公式；
  不只比较显示文字，也独立比较XML单元格类型。
- 输入CSV逐字节等于预期，保存、重开均不改变原件。
