## 实现结论

- Windows 使用 `ShellExecuteExW` 直接接收原样 UTF-16 路径，不经过 cmd，也没有启用环境变量展开标志。路径缓冲区活至调用结束；COM 成功初始化与反初始化配对，`RPC_E_CHANGED_MODE` 不错误反初始化。缺失/NUL 路径在启动前失败，Shell 失败按系统错误返回。
- 附件在创建目录及文件之前验证单个普通文件名。绝对/父级/多段路径被拒绝；Windows 额外拒绝 ADS、设备名、尾点空格等。原有中文、空格及碰撞另存语义保留。当前 UI 生成固定名称，报告没有把库入口缺陷夸大为已证明的 UI 攻击链。
- OLE 扫描按完整128字节块遍历，包含最后完整项，短输入和残缺尾段不会越界。此修改没有被描述为完整 OLE 格式验证器。
- 日志转接在64KiB记录上限后丢弃整行并继续排空，避免将同一长行尾部误认作新记录；中断读取、分块 UTF-8、EOF、下一条正常错误及上限边界有回归。未知输出仅汇总计数，未引入正文日志。
- 启动日志裁剪从同一文件句柄读取长度并定位到尾部，限制实际读取预算，保留原有完整行裁剪方式。并发缩短及零预算不按旧长度切片。
- 事件快照仅复制需要保留的字段，不再复制后丢弃一次性列表。未消费事件合并规则不变，快照测试覆盖保留字段及一次性字段清除。
