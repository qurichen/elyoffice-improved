## 复现与修复

旧实现统计首个物理字节行中的逗号、分号、制表符和竖线。它会把引用字段里的
标点算成分隔符，忽略引用记录的换行，并把多字节编码内的字节当成标点。
例如 `"a,b,c";00123` 应是两列；`Name,"a;b;c"` 应按逗号分列。

现在先确定编码，再严格解码，单次扫描首条完整记录：在字段起点识别引号，
引号内部的分隔符和换行不参与计数，成对双引号留在引用字段内。字段边界按
四个候选字符识别，也覆盖非首字段；非引用字段中间的字面引号不跨行遮蔽
后续记录。普通候选优先级、空文件/单字段默认逗号以及TSV/TAB扩展名保持。
解码失败仍由既有扫描明确标记为不可导入，不做替换字符解码。

首次候选实现逐个候选分隔符调用解析器比列数，独立R1预核发现它仍会误判
非首字段。该中间实现未交付；最终改为引用区间外计数，并另加冻结反例。

## 范围与后续

分隔符推断仍是启发式，不能消除无引号混合标点等文件固有的歧义；用户仍可
检查预览并更改分隔符/编码/列类型。本轮未实现严格禁止自动类型转换、每列
转换差异预览、超大CSV流式处理或本地查询，原路线已有这些方向，无需重复
新增路线项。测试中的前导零、长整数文本保护沿用已有列类型扫描，本轮使
相应样本在正确分列后走通该保护，不称为全新类型推断引擎。

实际Book/LOK测试使用测试窗口上下文；原生恢复和关闭检查另有范围，不等于
真实CSV导入对话框的系统鼠标/输入法验收。真实收到的复杂文件、多DPI、
系统IME、原生加密恢复、多日使用和完整安装升级验收仍开放。
