## 实际窗口流程

每个应用使用新建的测试目录、从仓库模板复制的输入文件和独立进程Job：

1. 启动当前优化版，等指定输入文件的打开记录及其后的首个图块。
2. 表格经名称框/公式栏输入A1文字与B1的`=1+2`；演示经Slide菜单插入一页。
3. 用中文、空格且无后缀的名称另存，检查生成XLSX/PPTX和预期内容。
4. 表格再填A2草稿；演示再插一页。取消另存，确认没有目标文件，再普通保存，
   核对这些后续编辑仍在，而不是只核对取消前的旧内容。
5. 对预先复制的guard目标触发真实原生覆盖确认，选择“否”，确认其字节未变。
6. 显式另存为ODS/ODP，检查内容，且没有多追加原来的默认后缀。
7. 正常关闭，确认原输入未变；用另一个新资料目录打开指定ODS/ODP，核对
   打开记录、后续首图块、正常退出、无残留Job进程和文件未被重写。

所有输入仅发送到本次创建的窗口。最终脚本不请求抢占前台，不用全局键盘、
剪贴板或系统输入法。字符和按键是发往窗口的合成消息，不是系统IME验证。
失败时只停止所属Job，不按全局进程名结束软件。

## 收紧证据，避免误判

独立R1指出两个缺口：只搜索共享字符串或整份ODF文本，可能把未被单元格
引用的残留文字算作保存成功；只等任意首图块，也不足以证明指定重开文件成功。

修正后，读法按实际A1/A2/B1定位，解析XLSX共享字符串索引、inlineStr或ODF
行列重复结构。B1必须是精确的`1+2`或`of:=1+2`，且B1自己的缓存值为3。
重开必须先出现指定文件名的打开记录，再有其后的首图块。

新增14个最小XML/ZIP与日志控制，覆盖未引用字符串、文字在其他格、错误公式、
其他格恰好为3、inlineStr、错误打开文件及过早首图块。它们验证检查器本身，
不是完整Office文件的兼容性证明。R2独立核对了这些控制、最后运行结果和四个
脚本/辅助文件哈希，未要求第三轮。

初期表格失败还查明了按键脚本问题：当前钉住的GPUI在消息队列的加速键处理
中把普通keydown交给GPUI；直接同步发送keydown没有走该入口。最终把按键和
字符按顺序投递到本次窗口队列，并提供扫描码。激活前台的诊断尝试被系统拒绝，
该实验保留为失败，最终实现已删除激活逻辑；没有修改Windows前台限制策略。
