# 第18轮：表格数据操作保持原始目标

2026-10-25。接续第17轮的读取状态契约，修复排序、标准筛选、分列和列按钮
菜单丢失来源的问题。只用合成数据、隔离资料目录与E盘构建，不更改安装版。

## 最终实现

- Sort、Filter、Columns保存 `data_of` 在同一worker锁内读取范围时得到的
  `Doc`，确认经 `run_on` 执行。随后选区或工作表变化，旧确认被拒绝。
- 共用 `Commands::run_all_on` 接受明确来源；既有 `run_on`、`run_all_in`
  复用该入口。列菜单定位与排序/筛选进入同一个严格批次，验证原始修订及
  全部参数后按顺序执行，过期时不先定位到新工作表。批次不提供失败回滚。
- 列菜单请求在首次客户端处理时保存 `RequestRead`，每个请求计数只捕获
  一次。它保留原Doc、工作表、表结构状态及关联的真实鼠标按压序号，等待
  释放期间不重新绑定到当前工作表。
- 视图分别记录真实Down/Up落地结果的精确Doc，取自各自 `Landed.now`，
  先于视图修订取max。只接纳同一次按压的释放、相差一次修订且没有其它
  上下文变化的情况；当前Doc必须就是该Up，原票据必须匹配Down或Up。
  没有关联按压的请求要求原Doc完全一致。正常慢点击、快速点击均有控制。
- 指针仍按下或队列未落地时保留请求，真实Up照常发送；落地后的既有
  Reported路径重试。获准后在同一worker锁内先核对 `worker.now` 再读取
  条目，回调返回时再次核对同一票据，不用最新Doc替换旧来源。
- 过期请求复用已有中英文状态变化通知。列菜单移到 `data/column.rs`，
  配对上下文移到 `view/pointer.rs`；本轮14份Rust源码均不超过500行。

未增加轮询、IPC消息、worker改动、依赖或C++补丁。继续复用第17轮兼容
worker及现有内核；不宣称重新构建了它们，也未新增插件运行时或统一事务。
